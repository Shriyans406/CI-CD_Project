# CI/CD DevOps Project

This repository demonstrates a simple CI/CD pipeline using GitHub Actions, Docker, and shell scripts. It hosts a simple web application designed to show continuous integration and deployment in action.

## Project Structure

```
├── .github/
│   └── workflows/
│       └── pipeline.yml       # GitHub Actions workflow for automated CI/CD
├── app/
│   └── app.py                 # Simple Flask web application
├── docker/
│   └── Dockerfile             # Docker instructions to containerize the Flask app
├── scripts/
│   ├── build.sh               # Local script to build the Docker image
│   ├── deploy.sh              # Local script to start the Docker container
│   └── stop.sh                # Local script to stop the Flask application (if run natively)
└── logs/                      # Log files generated by local build and deploy scripts (ignored in git)
```

## Features

- **Flask Application:** A basic Python web server with two routes:
  - `/`: Returns "CI/CD Pipeline Working Successfully"
  - `/health`: Returns "Application is healthy"
- **Dockerization:** Containerizes the Flask application with Python 3 and a virtual environment inside a Debian-based container. 
- **Local Scripts:** Includes utilities to build standardly versioned docker images and deploy them seamlessly.
- **GitHub Actions Pipeline:** A pre-configured action running on every push to the `main` branch to automatically build and deploy the container.

## Getting Started

### Prerequisites
- Docker engine and Docker CLI should be installed.
- (Optional) Python 3 installed natively if using `stop.sh` locally outside of docker.

### Local Development and Deployment

1. **Build the Application**
   Run the build script to generate a versioned Docker image.
   ```bash
   ./scripts/build.sh
   ```
   *This outputs logs to `logs/build.log` and saves the current build timestamp in `.version`.*

2. **Deploy the Container**
   Deploy the docker image locally using the port 5000, cleaning any existing containers named `ci-cd-container` to avoid conflicts.
   ```bash
   ./scripts/deploy.sh
   ```
   *This reads the `.version` generated from the build step and brings up the application at `http://localhost:5000`.*

3. **Check Application Status**
   Visit `http://localhost:5000/` and `http://localhost:5000/health` in your browser.

### Native Execution (Without Docker)
If you decide to execute `app/app.py` natively using `python app/app.py`, you can smoothly stop its execution by running:
```bash
./scripts/stop.sh
```

## Continuous Integration and Deployment (CI/CD)

The project includes an automated pipeline configured within `.github/workflows/pipeline.yml`. 
On every `push` to the `main` branch, it automatically:
- Checks out the code.
- Uses Docker Buildx.
- Builds the `ci-cd-app` image.
- Deploys the `ci-cd-container` detached, mapping port 5000.
